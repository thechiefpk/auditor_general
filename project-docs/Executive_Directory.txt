Slide: Network Audit – Overview

“Now I’ll demonstrate the Network Audit feature of my system.

The goal of this module is to assess the security of public‑facing web applications from the outside, in the same way an attacker or external auditor would see them.

The user simply enters a target URL, such as open.spotify.com , and the system performs a series of automated checks:

- It sends a real HTTP request to the server and captures the status code and all response headers .
- It analyzes the presence of critical security headers , such as HSTS, Content Security Policy, X‑Frame‑Options, X‑Content‑Type‑Options, and Referrer‑Policy.
- In parallel, it performs a small port scan of common service ports like 22, 80, 443, 3389 and others, to identify unnecessary externally exposed services.
- It also inspects the page content for potential PII leakage , such as email addresses, phone numbers, or hard‑coded API keys.
All of these findings are then combined into a single security score from 0 to 100. Missing headers, risky open ports and data leakage will all reduce the score. This gives a non‑technical stakeholder an immediate sense of risk, while still exposing full technical details for security engineers.”

Slide: Example – Spotify Network Audit

“Here is an example network audit of open.spotify.com .

The system gave this target a score of 70 out of 100 , which it classifies as ‘Fair’ security. That means the site is generally well configured, but still has some gaps.

Under ‘Connection Details’, we see that the target is reachable and returns HTTP 200 OK , so the system is talking to the real service in real time.

In the Open Ports section, the scanner found ports 80 and 443 open:

- Port 80 is plain HTTP. The tool flags this as unencrypted HTTP traffic and recommends redirecting all traffic to HTTPS.
- Port 443 is HTTPS, which is standard, but the tool reminds the user to enforce modern TLS versions and strong cipher suites.
The Missing Security Headers section highlights more subtle configuration issues:

- The site is missing X‑Frame‑Options , which means it could be vulnerable to clickjacking . The recommendation is to set this header to DENY or SAMEORIGIN .
- It is also missing a Referrer‑Policy header, which can cause sensitive URLs to be leaked to third‑party sites via the browser’s Referer header. The recommended fix is to set Referrer-Policy: strict-origin-when-cross-origin .
These findings are not synthetic or hard‑coded. They are generated by live HTTP requests and TCP connections to the target, and the resulting report can be exported as a PDF for auditors or management.”

Slide: Value for Organizations

“In practice, this feature gives organizations a quick way to:

- Discover missing defense‑in‑depth headers that are often overlooked.
- Identify unnecessary open ports that expand the attack surface.
- Detect early signs of data leakage in their public pages.
- Track their security posture over time through stored reports and PDFs.
Because the scanner is external and non‑intrusive, it can be run safely against production systems to validate hardening measures before and after changes.”
